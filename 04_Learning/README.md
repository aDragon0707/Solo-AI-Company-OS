---

## 1. Learning Philosophy

The founder does not need to become a full-time engineer.

The founder must learn to ask:

1. Why does this module exist?
2. Where does it fit in the system topology?
3. What input does it consume?
4. What output does it produce?
5. What risk does it control?
6. What must never be changed casually?

This is CEO-level technical literacy.

---

## 2. Teaching Standard

AI-05 must teach using:

```text
Architectural Intent First, Code Deconstruction Second.
```

Do not start with syntax unless syntax is the blocker.

Start with the system reason. Then identify the critical path. Then explain code details.

## 5. First Learning Goal

At the end of the first week, the founder should be able to say:

```text
[Project Name] has a planned topology.
Each module exists to protect a specific flow, decision, or risk boundary.
I can identify where a module sits before asking how its code works.
```
