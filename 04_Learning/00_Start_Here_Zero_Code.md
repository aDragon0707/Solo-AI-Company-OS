# Start Here - Zero-Code Founder

**Purpose:** Begin learning the system without getting lost in implementation details.

---

## 1. Code Is Not the Starting Point

Do not begin by reading every line.

Begin by asking:

```text
Why does this part exist?
What job does it do in the whole system?
What would break if it lied, guessed, or disappeared?
```

Only after that should you ask how the code works.

---

## 2. The Founder Reading Order

For any module, read in this order:

1. Intent: why it exists.
2. Topology: where it sits.
3. Input: what it receives.
4. Output: what it produces.
5. Risk: what it must protect.
6. Code: how the critical path works.

---

## 3. Basic Terms

`module`

A part of the system with a specific job.

`input`

What the module receives.

`output`

What the module returns, writes, or changes.

`critical path`

The few steps that must work for the system to be trustworthy.

`boundary`

A line a module or AI employee must not cross.

---

## 4. First Assignment

Pick one module or file in [Project Name].

Write:

```text
This module exists because:
It sits after:
It sits before:
Its input is:
Its output is:
It must never:
```

That is enough for Day 1.
