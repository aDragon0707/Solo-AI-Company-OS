# Public Pain Research Synthesis

**Purpose:** Translate public pain signals into positioning and product decisions for Solo-AI-Company-OS.

This file summarizes patterns. It does not replace founder decisions.

---

## Current Strong Patterns

1. AI users do not only need better prompts. They need context that survives sessions.
2. Handoff is a repeated pain, especially when work spans multiple AI windows or terminals.
3. Solo founders are becoming one-person operating teams, not just side-project builders.
4. The bottleneck is shifting from building to feedback, distribution, coordination, and decision discipline.
5. Obsidian users want structure, but they dislike systems that become a hobby by themselves.
6. People already use MOCs, context files, session notes, and handoff docs as workarounds.
7. Most adjacent tools are either coding-agent-heavy or plugin-heavy. There is room for a plain-text operating layer.

---

## Positioning Implications

Use this language:

```text
Stop losing your AI company inside chat history.
```

```text
Human decides. AI executes. Worklogs capture experience. Skills make it reusable.
```

```text
A lightweight Markdown operating system for one-person companies coordinating AI workers.
```

Avoid this language:

```text
AI cofounder
second brain template
automatic agent platform
all-in-one AI workspace
prompt pack
```

The strongest angle is not "AI can do everything." The stronger angle is:

```text
AI makes solo operators faster, but speed creates coordination debt. This repo keeps the debt visible.
```

---

## Product Implications

Keep improving:

- `FIRST_30_MINUTES.md`
- AI-01 onboarding
- worklog handoff quality
- skill memory layer
- dashboard update rules
- AI text maintenance protocol
- fictional examples that show one-person company operations

Do not rush:

- full automation
- plugin architecture
- databases
- dashboards that require a web app
- many specialized presets

The free Core should stay boring, inspectable, and easy to fork.

---

## Launch Implications

Good launch framing:

```text
I built this because my AI work was disappearing into chat history.
```

```text
This is not a prompt pack. It is a plain-text operating system for working with AI over time.
```

```text
If you are already juggling AI chats, project notes, decisions, and half-finished handoffs, this is for you.
```

Questions to ask early testers:

1. Where did you hesitate during setup?
2. Did `FIRST_30_MINUTES.md` make the first session obvious?
3. Did the decision log / AI employee / worklog loop make sense?
4. Which file felt unnecessary or intimidating?
5. What phrase would you use to describe the problem this solves?
