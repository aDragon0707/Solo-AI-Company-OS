# Solo-AI-Company-OS v2：认知操作系统路线图

## 愿景：骨架之上的神经系统

Solo-AI-Company-OS v1 是一个**组织骨架**。它使用 Markdown 和 Obsidian 建立纪律，将思考与决策分离。它对人类可读、设计上轻量、透明，并且今天即可部署，无需复杂的基础设施。

版本 2 代表了**可选智能执行层（神经系统）**。当单人创始人扩展其 AI 自动化时，他们最终可能会遇到"上下文税"——即 AI 代理读取静态 Markdown 文件夹变得过于缓慢或昂贵。V2 概述了将这种静态记忆转化为活跃的、事件驱动架构的未来方向。

**核心原则：**
V2 并**不**取代 V1。V2 是一个可选的工具包，包含派生状态和可查询接口，构建在 V1 Markdown 基础之**上**。

---

## 反目标（V2 永远不会做的事）

为了保持该操作系统的实用性，未来架构严格遵循以下约束：
* **不要求使用 v1 就需要重型基础设施。** 单人创始人绝不应仅仅为了运行基础 OS 就需要 MCP 服务器或 LangGraph。
* **不取代创始人决策日志。** Markdown 仍然是最终的真相来源。
* **不覆盖原始工作日志。** AI 执行过程中混乱的现实必须保持可见。
* **不将每个收件箱想法自动转化为任务。** 创始人必须有空间发泄和头脑风暴，而不会触发全系统执行。
* **不对每个琐碎输出进行红队审查。** 对抗性审查应保留给高风险操作，以防止系统变得缓慢且成本过高。

---

## 四个未来模块（可选架构）

### 1. 可查询上下文接口（动态上下文）
不再强制 AI 顺序读取庞大的 `ROLE.md` 和 `Decision_Log.md` 文件，未来的实现将探索 MCP 风格的接口。
* **概念：** 从静态读取转向动态查询（例如，`get_active_constraints(role, task)`、`get_latest_decision(topic)`）。
* **优势：** 减少 token 膨胀，保持上下文窗口高度聚焦。

### 2. 派生状态图（结构化记忆）
原始 Markdown 工作日志作为人类可读的"法律记录本"（未经编辑的日常工作现场记录），系统最终将支持机器可读的派生层。
* **概念：** 一个运营视图，将已完成的工作日志转化为 JSON 事件流或状态图。
* **优势：** 允许复杂的 AI 代理快速理解当前项目状态，而无需阅读数周的叙述文本。

### 3. 决策输入工作流（认知输入）
`FOUNDER_Thinking_Inbox.md` 仍然是一个自由形式的区域，用于存放焦虑、想法和抱怨。V2 引入了一个**仅在请求时激活**的缓冲区。
* **概念：** 当创始人明确要求将某个想法正式化时，苏格拉底式对话引擎会帮助将原始想法提炼为架构论点，然后再提交到决策日志。
* **优势：** 防止不成熟的想法立即变成强制性的 AI 任务。

### 4. 红队审查关卡（对抗性安全）
AI 员工之间的同行评审常常导致"迎合"和共享幻觉。V2 提出了隔离的红队关卡，严格作为拦截器使用。
* **概念：** 一个网关模型，不进行修复或美化，只拒绝违反创始人决策日志的输出。
* **阈值：** 仅部署在高风险关键节点（例如，公开主张、定价变更、生产合并或核心真相升级）。
