# 产品边界

**目的：** 明确哪些内容属于免费开源的 Core，哪些可以成为未来的 Pro Pack，以及哪些绝对不能隐藏在付费访问之后。

---

## 产品模式

Solo-AI-Company-OS 应该是一个自助产品。

公共仓库通过自身的有用性赢得信任。付费产品应节省时间、增加深度并提供专业化的变体，但不能让 Core 变得不完整。

```text
免费 Core = 可用的操作系统
Pro Pack = 更快的设置、更丰富的示例、更深入的变体
```

---

## 免费 Core 包含内容

免费仓库应保留：

- 稳定的文件夹结构
- `OBSIDIAN_HOME.md`
- 创始人思考、决策和回顾分类账
- 公司状态仪表板
- AI-01 到 AI-05 的基础角色和启动提示词
- 协调协议
- AI 文本维护协议
- 工作日志索引和工作日志模板
- 学习实验室
- 声明边界原则
- 最小交接提示词
- 至少一个虚构的第一天示例
- 许可和贡献规则
- 基本的自助初始化路径
- 基础的发布验证和打包脚本

Core 必须在不付费、无服务器、无数据库、无付费工具的情况下可用。

---

## 未来 Pro Pack 可能包含内容

未来的付费包可能包括：

- 更丰富的 vault 生成器选项
- 打包好的 ZIP 发布版本
- 额外的虚构示例 vault
- 第 1 天、第 7 天和第 30 天的操作流程
- 针对不同类型创始人的角色包
- 高级 AI 员工提示词
- 更详细的审查清单
- 简短的使用指南或视频
- 用于打包和验证的便捷脚本

这些资产应使采用更快。它们不应成为理解或运行基础操作系统的必要条件。

---

## 绝不可以锁定为付费的内容

不要将以下内容设为付费专享：

- 创始人决策日志
- 工作日志模板
- AI-01 协调角色
- 基础的 AI 员工模型
- 公司状态仪表板
- 系统原则
- 声明边界规则
- 交接纪律
- 基础的初始化路径
- 核心 README 和上手引导

如果用户无法从免费仓库运行基础操作系统，那么边界就失败了。

---

## 公共或 Pro 中不得包含私人数据

不要包含：

- 真实的客户姓名
- 私人的公司笔记
- 私人的创始人反思
- 专有的项目细节
- 来自真实业务的内部销售材料
- 来自其他仓库的敏感技术实现说明
- 可以识别真实客户、产品或合作的示例

所有示例必须是虚构的。

如果某个示例受到真实工作的启发，请重写它，直到无法追溯到原始来源。

---

## 维护规则

在添加功能时，请问：

```text
这个功能让免费 Core 变得更清晰、更有用吗？
还是它属于未来的 Pro 便利层？
```

Core 的改进应减少混淆。

Pro 的改进应减少设置时间或增加专业深度。
