# 贡献指南

感谢你帮助改进 Solo-AI-Company-OS。

本项目刻意保持轻量。贡献应使系统更清晰、更易上手，对使用 AI 员工的创始人来说更安全。

---

## 贡献理念

核心模板应保持：

- 以 Markdown 为优先
- 人类可读
- 易于复刻
- 无需付费工具即可使用
- 无需复杂设置即可使用
- 严格维护创始人决策权威
- 严格区分已验证的真相与公开故事

有疑问时，优先选择清晰而非巧妙。

---

## 好的贡献

以下贡献是受欢迎的：

- 更清晰的上手引导文案
- 使用完全虚构的公司的更佳示例
- 改进的 AI 员工角色提示词
- 更强大的工作日志和交接模板
- Obsidian 导航改进
- 小的学习实验室内容补充
- 打字错误和断链修复
- 不带炒作地解释系统的发布材料
- Issue 模板和 Pull Request 模板

---

## 需要谨慎的贡献

以下内容可能合适，但应事先讨论：

- 新的 AI 员工角色
- 新的顶层文件夹
- 高级自动化
- 与付费工具的集成
- 对决策日志模型的更改
- 对 V2 路线图的更改
- README 的大幅重写

在基础的 Markdown 版本被证明有用之前，项目不应变得过于繁重。

---

## 超出范围

请避免：

- 添加真实公司数据
- 添加客户名称、私人笔记或专有项目细节
- 将仓库变成任务应用的克隆
- 用 AI 生成的决策替代创始人决策
- 在 V1 中要求数据库或服务器
- 添加没有实际示例的模糊生产力语言
- 添加鼓励 AI 猜测缺失事实的提示词

---

## 示例数据规则

示例必须是虚构的。

使用虚构的名称、虚构的产品、虚构的客户和虚构的场景。如果某个示例受到真实工作的启发，请重写它，直到无法暴露真实的公司、客户、个人、市场计划或内部技术细节。

---

## Pull Request 清单

在提交 Pull Request 之前：

- 阅读 `README.md`
- 阅读 `00_System_Brain/System_Principles.md`
- 确保你的改动保持 V1 的轻量化
- 只使用虚构数据
- 检查链接是否指向存在的文件
- 解释你的改动如何帮助独立创始人更清晰地运营 AI 工作

---

## 维护者审查标准

当一个改动帮助新创始人更快地回答以下问题时，它就是好的贡献：

- 我决定了什么？
- 哪个 AI 应该做这件事？
- 上一个 AI 实际做了什么？
- 哪些事情仍需要创始人判断？
- 什么是已验证的，什么仍然只是草稿？

如果一个改动让这些答案变得更难看到，它可能不属于核心模板。
