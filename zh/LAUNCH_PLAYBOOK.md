# 发布手册

**目的：** 帮助维护者清晰地发布 Solo-AI-Company-OS，而不过早陷入炒作或繁重的软件。

---

## 发布定位

使用这条痛点优先的宣传语：

```text
别再让你的 AI 公司迷失在聊天历史里了。
```

然后用一句话解释项目：

```text
一个为管理 AI 员工的独立创始人打造的有纪律的 Markdown 操作系统。
```

项目应被定位为一个实用的操作系统，而不是一个提示词包。

---

## 首先触达谁

从已经感受到痛点的人群开始：

- 每天使用 AI 的独立创始人
- 借助 AI 交付产品的独立开发者
- 使用 Markdown 管理项目的 Obsidian 用户
- 在客户工作中运行多个 AI 聊天的顾问
- 试图理解技术项目的非技术创始人

避免像"适用于每个使用 AI 的人"这样的宽泛传播。第一批受众应该足够精准，能够立即识别出自己。

---

## 公开发布资产

在正式发布之前，准备好：

- 清晰的 README 首页
- 系统地图图片
- `EXAMPLE_DAY_1.md`
- 许可文件
- 贡献规则
- 发布清单
- 验证和打包脚本
- 一篇简短的发布文章
- 三张截图或图片预览

第一个公开版本应展示工作流程，而不仅仅是文件夹树。

---

## 发布文章结构

使用这个结构：

1. 问题：AI 工作消失在聊天历史中。
2. 代价：决策、交接和项目真相变得模糊。
3. 解决方案：一个以 Markdown 优先的公司记忆系统。
4. 演示：展示创始人决策日志、AI 角色和工作日志交接。
5. 边界：V1 不需要服务器、数据库或付费工具。
6. 邀请：复刻它、改造它、分享遇到的问题。

简短版本：

```text
我构建了一个开源的 Markdown 操作系统，供管理 AI 员工的独立创始人使用。

它将散乱的 AI 对话转化为创始人决策、角色提示词、工作日志、交接和学习循环。

核心规则：AI 可以执行和质疑，但创始人决策仍然是真相的来源。
```

---

## 建议的发布渠道

在人们已经讨论 AI 工作系统的渠道进行发布：

- GitHub
- X
- Hacker News Show HN
- Reddit 上的 Obsidian、独立开发者社区和 AI 工作流社区
- Indie Hackers
- 在 README 和示例看起来足够完善之后，再上 Product Hunt

先在较安静的渠道发布。利用第一批反馈修正令人困惑的措辞，然后再进行更广泛的发布。

Show HN 只有在公共仓库易于试用之后才适合。不要提交纯落地页或筹款页面。

Product Hunt 最好在你拥有视觉素材、简洁标语和清晰的创作者故事之后再上。

在广泛发布之前，请运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\validate-release.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\package-release.ps1 -Version '0.1.0'
```

## 收费建议

保持核心仓库免费且开源。

付费路径应该是自助的，而不是依赖创始人的咨询服务。

推荐模式：

| 层级 | 价格策略 | 原因 |
|---|---|---|
| 免费 Core | 免费 | 建立信任、采用率和公开证明 |
| Pro 模板包 | 付费 | 为购买者提供更完整的开箱即用包 |
| 自动化设置工具 | 付费或与 Pro 捆绑 | 节省设置时间，无需实时帮助 |
| 角色包 | 付费 | 服务于特定类型的创始人，无需定制工作 |
| 包更新 | 付费升级或免费更新 | 让产品持续改进 |
| GitHub Sponsors | 可选的后续方式 | 在用户已经认可仓库价值后支持维护 |

免费的仓库应保持足够完整以供使用。Pro Pack 应节省时间并增加深度，而不是解锁基础系统。

好的付费资产（未来方向）：

- 一键 vault 生成器
- 更丰富的 AI 员工角色包
- 创始人、顾问、创作者和代理公司的变体
- 第 1 天、第 7 天和第 30 天的操作流程
- 更大的虚构示例 vault
- 打包好的 release ZIP 文件
- 简短的设置视频或书面指南

避免让业务依赖于：

- 手动设置电话
- 定制 vault 清理
- 持续的私人支持
- 承诺手工修复每个用户的工作流程

如果提供私人帮助，它应该是罕见的、昂贵的，并且明确超出常规产品的范围。默认的买家体验应该是自助的。

---

## 贡献边界

项目应接受让核心更清晰的改进。

接受：

- 更好的示例
- 更清晰的角色提示词
- 上手引导的改进
- 更安全的交接格式
- 拼写和链接修复
- 小的导航改进

谨慎对待：

- 新的顶层文件夹
- 重型自动化
- 特定工具的工作流程
- 系统原则的大幅重写
- 需要服务器或付费账户的功能

拒绝：

- 真实的私人公司数据
- 模糊的 AI 炒作
- 允许 AI 猜测缺失事实的提示词
- 削弱创始人决策权的改动
- 让 V1 依赖 V2 的改动

---

## 第一个成功指标

第一个成功指标不是星星数。

第一个成功指标是：

```text
一个新的创始人能否在 15 分钟内完成设置，并理解下一步该做什么？
```

如果可以，那么星星、复刻、帖子、付费服务和 V2 自然会随之而来。
