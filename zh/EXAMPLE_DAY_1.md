# 第一天示例

**目的：** 展示填满内容的第一天可能是什么样子，而不使用真实的公司、客户或产品。

本示例完全虚构。请将名称、目标和约束替换为你自己的。

---

## 虚构设定

| 字段 | 示例 |
|---|---|
| 公司 | Northstar Notes |
| 产品 | BriefForge |
| 创始人 | 独立运营者 |
| 当前阶段 | 从想法到第一个可用的原型 |
| 主要风险 | 在明确报价之前就开始构建功能 |

BriefForge 是一个虚构工具，帮助顾问将冗长的客户笔记转化为简短的跟进备忘录。

## 1. 创始人思考收件箱

文件：

```text
01_Founder/FOUNDER_Thinking_Inbox.md
```

示例条目：

```markdown
## 2026-05-02 - 原始想法

我一直在让 AI 提供策略、文案和产品计划，但输出总是混在一起。

当前的焦虑：
- 我可能在证明第一个买家问题之前就构建得太多了。
- 我不希望 AI 在未经我批准之前将想法变成承诺。
- 我需要一个地方让决策正式化。

可能的第一个客户：
- 需要撰写大量客户跟进内容的独立顾问

不清楚：
- 第一个产品应该是一个模板 vault、一个小型应用，还是一个服务包
```

## 2. 创始人决策日志

文件：

```text
01_Founder/FOUNDER_Decision_Log.md
```

示例条目：

```markdown
## DEC-20260502-001 - 建立 AI 操作边界

状态：活跃
日期：2026-05-02

决策：
AI 员工可以起草选项、计划和评审意见，但不得将任何草稿转化为创始人决策。

原因：
公司需要持久记忆，但创始人必须仍然是策略、承诺和风险的最终所有者。

适用范围：
- 产品方向
- 客户声明
- 定价
- 公开写作
- 技术范围

AI 指令：
当任务需要决策时，标记为[需要创始人决策]，而不是猜测。

审查日期：
2026-05-09
```

## 3. 第一次 AI-01 请求

需要打开的文件：

```text
03_Company/AI_Employees/AI-01_Founder_Office/START_PROMPT.md
```

示例创始人消息：

```text
AI-01，请阅读创始人决策日志、Obsidian 主页、公司地图和工作日志索引。

然后告诉我：
1. 第 1 天的前 3 个优先级
2. 当前的阻碍因素
3. 需要做出的创始人决策
4. 下一步应该由哪个 AI 角色负责
```

示例 AI-01 输出摘要：

```markdown
## AI-01 第一天路由

最高优先级：
1. 定义第一个买家及其痛点的用例。
2. 创建一个清晰的报价页面草稿。
3. 在分享任何内容之前，请 AI-04 审查声明。

当前阻碍因素：
- 未确认的买家细分群体
- 未批准的公开承诺
- 尚无工作日志

需要创始人决策：
- 选择第一个买家细分群体
- 决定第一天的输出是服务、模板还是应用原型

下一步负责人：
- AI-03 应起草买家假设和外联角度。
- AI-04 应在草稿存在后审查声明边界。
```

## 4. 第一份工作日志

文件：

```text
03_Company/AI_Worklogs/WORKLOG_TEMPLATE.md
```

示例填写条目：

```markdown
## AI-01 工作日志 - 2026-05-02 - 第一天系统路由

### 收到的任务
- 阅读系统入口文件，为创始人提供第一天优先级、阻碍因素、需要做出的决策和下一个 AI 负责人。

### 已读文件
- OBSIDIAN_HOME.md
- 01_Founder/FOUNDER_Decision_Log.md
- 03_Company/MOC_Company.md
- 03_Company/AI_Worklogs/WORKLOG_INDEX.md

### 已完成的工作
- 确认创始人决策是真相的来源。
- 确定第一天优先级。
- 标记了缺失的买家和报价决策。
- 推荐 AI-03 负责第一个买家的相关工作，AI-04 负责声明审查。

### 文件变更
- 无。

### 验证状态
- 未运行。
- 这仅是一个计划和路由任务。

### 未完成事项
- 尚未选择买家细分群体。
- 尚未起草报价页面。

### 需要创始人
- 选择第一个买家细分群体。
- 决定第一个输出是服务、模板还是应用原型。

### 需要另一个 AI
- AI-03 负责买家和报价草稿。
- AI-04 负责草稿存在后的声明审查。

### 给下一个 AI 的交接说明
交接给：AI-03 增长 / 收入
交接原因：需要第一个买家假设和外联角度。
当前状态：第一天优先级已确定，但买家和报价尚未批准。
已读文件：OBSIDIAN_HOME.md, FOUNDER_Decision_Log.md, MOC_Company.md, WORKLOG_INDEX.md
已变更文件：无
验证状态：仅规划
已知差距：没有创始人批准的买家细分群体
下一个 AI 需要：起草买家选项，不做最终决定
不要假设：不要声称产品已通过验证
需要创始人决策：第一个买家细分群体

### 下一步建议
- 创始人在 AI-03 撰写外联内容之前，先选择第一个买家细分群体。
```

## 5. 第一天应该是什么感觉

经过一次简短的会话后，你应该拥有：

- 一条正式决策
- 一个已激活的 AI 角色
- 一份工作日志
- 一个明确的下一步负责人
- 一份仍需创始人决策的清单

这就足够了。第一天的重点不是填满每一个文件。重点是停止把公司丢失在聊天历史中。
