# 创始人学习实验室

**目的:** 帮助创始人以运营者和架构师的身份理解"我的AI协作操作系统"，而非被动使用AI输出的用户。

**导师:** `03_Company/AI_Employees/AI-05_Learning_Tutor/START_PROMPT.md`

---

## 1. 学习理念

创始人无需成为全职工程师。

创始人必须学会提问：

1. 这个 module 为什么存在？
2. 它在系统 topology 中处于什么位置？
3. 它消费什么 input？
4. 它产生什么 output？
5. 它控制什么风险？
6. 哪些东西绝不能随意修改？

这是 CEO 级别的技术素养。

---

## 2. 教学标准

AI-05 必须遵循以下方式教学：

```text
架构意图优先，代码解构其次。
```

不要从语法开始讲解，除非语法本身成为障碍。

从系统理由开始，然后识别关键路径，再解释代码细节。

## 5. 第一周学习目标

第一周结束时，创始人应该能够说出：

```text
我的AI协作操作系统拥有一个规划好的拓扑结构。
每个模块的存在都是为了保护特定的流程、决策或风险边界。
在询问代码如何工作之前，我能识别出模块所处的位置。
```
