# 创始人项目地图

**目的:** 帮助创始人通过 topology 而非代码来理解"我的AI协作操作系统"。

---

## 1. 通用项目流程

使用以下抽象地图：

```text
[计划/意图]
  -> [输入收集]
  -> [数据采集组件]
  -> [完整性验证]
  -> [分析/审查]
  -> [分析输出]
  -> [客户或内部决策]
```

---

## 2. 如何阅读一个 Module

对于每个 module，回答以下问题：

| 问题 | 答案 |
|---|---|
| 它为什么存在？ | [意图] |
| 什么在它之前？ | [上游 module] |
| 什么在它之后？ | [下游 module] |
| 它消费什么？ | [输入] |
| 它产生什么？ | [输出] |
| 它保护什么风险？ | [风险] |
| 它不能做什么？ | [边界] |

---

## 3. 初期不必深究的内容

刚开始时，不要追逐：

- 每个辅助函数
- 每个语法细节
- 每个配置选项
- 每个边界情况

先找到主路径，细节之后再说。

---

## 4. 创始人合格标准

当你能够说出以下内容时，你就合格了：

```text
这个模块的存在是为了保护[意图]。
它接收[输入]。
它产生[输出]。
如果它失败了，会发生[风险]。
它绝不能[边界]。
```
